When proposing a new external tool, library, service, or dependency, give a clear justification FIRST: (1) what it fundamentally does, (2) whether the existing toolset already does that, (3) the specific delta it adds. Don't list it as an option without that reasoning. Prefer exhausting the current tools + web research before reaching for a new dependency.

**Why:** The developer relies on the assistant to explain a tool's real value-add versus existing capability (they can't always independently evaluate a domain-specific library), and dislikes adopting things that duplicate what's already there.

**How to apply:** Before recommending a new tool, state the three points above; if it duplicates an existing capability, say so and don't adopt it. Complements [[clarify-misconception-before-costly-action]].
