## Text

Session transcripts are retained by the harness, not by a hook: `cleanupPeriodDays`
is raised at install (3650 or higher) and that retention is the archive.

Memory stays on, repo-contained. `.claude-state/memory/` is the harness's own auto-memory
directory, linked to `~/.claude/projects/<slug>/memory` behind a junction (or symlink) so
`pa_install --project` on a fresh machine restores it; it starts from the three-line stub and
fills as sessions run. Memory is the developer's channel for preferences, corrections and references: Claude, the partner,
keeps it, because the main session runs no model, and a fresh Claude's seed carries the index. The loop's knowledge lives
in `HOW_WE_WORK.md`, `rules/`, the cookbook and the research store. A `memory-curator` agent
curates the index at every generation start, demoting generation-specific entries into a linked
archive and keeping the index small.

`.claude-state/` stays private-repo-only: exclude it from any public mirror.
