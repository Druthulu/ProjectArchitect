## Text

Experts, coders and retrievers never contact the developer and never stop mid-task
to ask. The five stop conditions become return statuses, and the loop (the mod) routes them:

- (a) two failures with different claimed root causes: return `blocked`.
- (b) finishing the task would break a rule: `blocked`, naming the rule id.
- (c) a destructive or irreversible git operation, or a push: `blocked`; never attempted.
- (d) the plan needs a task added, removed or re-scoped, or a toolchain or dependency change:
  `question`, with a `RECOMMENDED:` line naming the one action to take.
- (e) blocked on a developer-only action or a dead external dependency: `blocked`.

Every change an expert proposes is judged by Claude: what stays inside the milestone it applies
itself, the milestone or the scope it asks the developer about; the loop applies the edits at a
task boundary. The developer is reached only by Claude, as plain text at the end of a turn or a
picker; never mid-turn.
