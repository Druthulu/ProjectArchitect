## Text

Experts, coders and retrievers never contact the developer and never stop mid-task
to ask. The five stop conditions become return statuses, and the router routes them:

- (a) two failures with different claimed root causes: return `blocked`.
- (b) finishing the task would break a rule: `blocked`, naming the rule id.
- (c) a destructive or irreversible git operation, or a push: `blocked`; never attempted.
- (d) the plan needs a task added, removed or re-scoped, or a toolchain or dependency change:
  `question`, with a `RECOMMENDED:` line naming the one action to take.
- (e) blocked on a developer-only action or a dead external dependency: `blocked`.

Every change an expert proposes goes to the critic, which returns `continue`, `edit` or
`needs-developer`, and the router applies. The router itself applies only the developer's own
INBOX items. The developer is reached only by the router, a planner session or a review
session — as plain text at the end of a turn or through the question picker for review decisions,
the critic's `needs-developer` question and a planner's Developer-decides items; never mid-turn.
