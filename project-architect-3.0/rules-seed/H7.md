## Text

`HOW_WE_WORK.md` and `docs/ops/<topic>.md` are updated in the same task that changes
what they describe: a tool, a command, an env var, a pin, a path, a hook, an MCP entry, a build or
test invocation. Not at phase end, not later. The task that changed it owns the edit and lists the
file in its `Files:` line.

Split of duty: `HOW_WE_WORK.md` carries the short operative facts (the tool table with this
machine's exact commands, paths, build/run/test, standing decisions) and stays near 3k tokens;
`docs/ops/<topic>.md` carries the detail, one topic per file, reached through `docs/ops/INDEX.md`.

The closer checks this at phase end: a task that changed the environment without touching either
file is recorded as a deviation in the PhaseEnd.

A keep-current document names the trigger that updates it and carries a checkable staleness
marker; a rule alone is not the mechanism (Vantage book map).
