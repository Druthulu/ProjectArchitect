## Text

One task per fresh context; commit at sub-task boundaries, never in batches.

Every commit goes through `bash tools/commit_task.sh <TaskId> "<one line>"`: explicit paths, never
`git add -A`, no AI trailers, never a push. A green coder run is a commit; a handoff is a commit;
the end of the task is a commit.

The record is the task's own two files, not a running phase log and not the commit body:
`phase-ends/current/logs/T<n>.md` is the full log, written once at the end, no size cap;
`phase-ends/current/tasks/T<n>.md` is the summary, at most 150 lines, and it is the only one of
the two that anything upstream reads. `task_log.py finish` lints both, and `plan_edit.py
set-status <T> done` refuses without a `Verified:` line in the summary.

Tasks run in plan order unless the plan's `deps:` or `wait-for:` says otherwise. Never interleave
two tasks in one context.
